# Léo Parpeix Hero 场景建模技术分析

## 总体结论

原始 `scene_v9.glb` 属于“轻量静态布景建模 + 烘焙贴图 + Web 压缩优化”，并不是复杂的实时 PBR 场景。

它的核心思路是：

```text
简单但轮廓准确的几何
        +
高质量烘焙纹理
        +
固定相机构图
        +
网页氛围与后处理
```

真正让画面显得丰富的重点不是高面数，而是美术构图、UV 烘焙和网页运行时的动态层。

## Blender 基础体块建模

GLB 中的网格来源名称包括：

- `Cube`
- `Plane`
- `Cylinder`
- `Roundcube`

这说明场景大量使用方块、平面、圆柱和圆角体完成基础形状，属于以基础体块为主的建模方式。

需要注意：GLB 只保存最终网格，无法确认原 Blender 工程具体使用了哪些修改器。

## 固定机位的舞台式建模

场景围绕唯一的 Blender 相机构图，相机垂直 FOV 约为 `22.9°`。

这种方式类似搭建一个只服务于特定镜头的舞台：重点制作相机能看到的区域，不必按照自由探索式 3D 场景制作所有方向。

## 选择性分配面数

整个 GLB 总计约：

- `28,743` 个顶点
- `22,796` 个三角面

部分模型的面数：

| 类别 | 三角面数（约） |
| --- | ---: |
| 花朵 | 7,238 |
| 主要家具 | 5,864 |
| 书架 | 3,019 |
| 地板 | 50 |

轮廓复杂、靠近镜头的花朵和家具使用更多面；墙壁和地板等规则表面保持极简。

## 按贴图类别合并网格

模型被整理为 13 个网格节点，并按照贴图类别命名：

- `TexFleur`：花朵
- `TexMobilier`：家具
- `TexProps`：摆件
- `TexTableaux`：画作
- `TexBibli`：书架
- `TexFloor`：地面
- `TexWalls`：墙壁

这表明多个独立物体被按贴图类别合并，减少网页运行时需要管理的对象和 Draw Call。

场景节点层级也非常扁平，模型变换基本已经应用到顶点数据，适合静态 WebGL 场景。

## UV 展开与纹理图集

所有网格都包含 `TEXCOORD_0` UV 数据，部分画作网格还包含第二套 `TEXCOORD_1`。

场景使用 7 张独立的 `2048 × 2048` KTX2 纹理图集，每个模型类别使用对应贴图，而不是为每件小物体单独加载纹理。

## 完整的光照烘焙

GLB 内没有嵌入材质、灯光、法线或切线，网格主要只包含：

```text
POSITION
TEXCOORD_0
部分模型还有 TEXCOORD_1
```

颜色、光照、阴影和大量材质细节主要已经烘焙到纹理中。网页运行时可以使用不受灯光影响的材质直接显示，不需要实时计算复杂 PBR 光照。

## Draco 几何压缩

13 个网格全部使用：

```text
KHR_draco_mesh_compression
```

压缩后整个 GLB 只有约 `142 KB`，浏览器加载后再使用 Draco 解码器还原几何数据。

## KTX2 / BasisLZ 纹理压缩

7 张 2K 烘焙纹理使用 KTX2/BasisLZ 压缩，总体积约 `1.8 MB`。

浏览器会根据设备能力，将其转码为 ASTC、BC、ETC 等 GPU 支持的纹理格式，从而降低网络传输和显存压力。

## 静态场景优化

GLB 中没有：

- 骨骼和蒙皮
- 变形动画
- GLB 动画轨道
- LOD 扩展
- GPU 实例化扩展
- 实时灯光
- 内嵌材质和纹理

这是一个专门服务于固定 Hero 画面的静态场景，因此不需要游戏场景那样的动态结构。

## 不属于建模文件的效果

以下效果由 Three.js 在网页运行时额外创建，不在 `scene_v9.glb` 中：

- 云雾 Sprite
- 漂浮粒子
- 鼠标惯性视差
- RenderTarget 合成
- GPU 速度场
- 流体拖影和画面扭曲
- 前景透明 WebGL 层

因此可以将整个 Hero 理解为两部分：

```text
Blender / GLB：几何、UV、固定相机和基础构图
Three.js / Shader：云雾、粒子、交互、合成与后处理
```
